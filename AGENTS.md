### Completed: data-plane watchdog (dpmon + wardend-watchdog) — the AF_XDP wedge backstop (Oct 22, lance/distros, wardend a0271ee / stagex 1aab9615d4)
- **The gap:** the AF_XDP wedge (all frames XDP_PASS to the offline kernel) previously required a manual reboot — the v13 supervisor/watchdog that self-heals on the old execd stack is NOT in the wardend stack. The regentd kill-deadline fix (96ba844) keeps a healthy warden alive but does NOT cover a data-plane wedge with a live warden. This adds a NEW, separate, minimal data-plane backstop.
- **The design (two processes, both separate from regentd + the warden):** (1) **dpmon** — an in-sandbox co-tenant of `bridge wire` (spawned by the bundle config.json argv's `--dpmon-bin /usr/bin/dpmon`), like seald/posternd/offline-srv. It does a real external TCP connect on a bounded cadence (10 s, targets 8.8.8.8:443 + 1.1.1.1:443) and publishes `<epoch> pass|fail` to the host-visible `/run/wardend/devices/dp.status` (the bind-mounted dir). **Staleness is the bound, not the probe:** a wedge that hangs the connect leaves the file stale. (2) **wardend-watchdog** — a host-side process, **a SEPARATE process from regentd + the warden** (the Oct 6 lesson: the supervisor loop itself wedged, so it cannot recover itself). regentd spawns it once at boot (`spawn_watchdog()`). It is **std** (like regentd + the warden bin — the no_std class is the warden lib, not the bins), built on the in-tree `sys` raw syscall layer, with **no runsc / pgrep / bpf(2) / serial on its path** (it cannot wedge the way the main supervisor could — the wedge vector was the supervisor blocking on a runsc child; this process never touches runsc).
- **The fire logic (5 s cadence):** read the dpmon status mtime + the warden heartbeat mtime; fire `reboot -f` when dp.status is stale ≥ 540 s (dp-dark) OR the heartbeat is stale ≥ 600 s (hb-stale). **An absent file is treated as FRESH (age 0), not stale** — the false-fire bug this session: `mtime_age` had `None => u64::MAX` (maximally stale), so a missing heartbeat (not yet written by the warden) immediately counted as 600 s stale and fired. Fixed to `None => 0`. An absent heartbeat means the warden has not written one yet, which must not fire the backstop on its own; a stale-but-present file is what the backstop is for. The main supervisor (regentd/warden) owns the fast path (120 s escalation: sandbox respawn); the watchdog is the BACKSTOP for when the fast path's owner is wedged. The warden's kill-deadline (96ba844) only fires when the heartbeat is ABSENT; this watchdog fires when the data plane is dark OR the heartbeat is stale (present but old) — the two do not overlap.
- **The persistent reboot-loop guard (raw disk tail bytes):** the disk is ESP-only (the OS runs from RAM, /run is a fresh tmpfs, no persistent FS is mounted), so the guard is a 64-byte block at the tail of the boot disk (magic `WDWDRB01` + count u64 + epoch u64 + pad). If the watchdog has rebooted `max` (default 5) times in a `window` (default 600 s), it STOPS rebooting and stays down (the machine needs a look, not another spin). The block survives reboot because it is raw disk bytes, not a filesystem. Env-overridable: `WARDEND_GUARD_DEV` (default `/dev/vda`; a file for QEMU), `WARDEND_GUARD_MAX`, `WARDEND_GUARD_WINDOW`, `WARDEND_DP_DARK`, `WARDEND_HB_STALE`.
