### Completed: regentd kill-deadline bug — the persistent terminal dark, root-caused + fixed (Oct 22, lance/distros)
- **THE ROOT CAUSE OF THE PERSISTENT DARK (the 50+ min wire darks that no watchdog recovered):** `regentd`'s `watch_warden` kill deadline fired **unconditionally** at 600 s (`spawn_at.elapsed() >= kill_deadline()`), **even when the warden's heartbeat was FRESH**. The respawn budget (3) then exhausted → `reboot -f` → (regentd is PID 1) `Kernel panic: Attempted to kill init`. This is ALSO the QEMU "regentd: wardend alive past the kill deadline; kill -9 (respawn) → respawn 1/3, 2/3, 3/3 → reboot -f (respawn budget spent) → Kernel panic" loop seen in the prior session — the same bug, not a separate issue. ### Completed: seald in-sandbox device I/O — mknod→bind-mount + gofer char-device fix (Oct 22, lance/distros)
- **The two walls that blocked seald's in-sandbox TPM2 quote, both fixed + QEMU-accepted:** (1) **mknod dev_t mangling** — the gofer's mknod round-trip clobbers the 20-bit `dev_t`, so `mknod`-created char nodes in the sandbox had the wrong rdev (open → EISDIR/EACCES). Fixed with a **bind-mount** of the host device into the sandbox (warden moat `758697f`, wire pass 4): `moat: probe: node … re-open O_RDWR (post-grant) errno=0` + rdev matches host exactly (tpmrm0 = 253:65536, tpm0 = 10:224). (2) **gofer char-device I/O (the deeper wall)** — the sentry's `directfs` handle (the ACTIVE I/O path for a donated host fd, `h.fd >= 0`) used `Preadv2`/`Pwritev2` with a real offset = `preadv`/`pwritev`, which return **ESPIPE ("Illegal seek") on non-seekable character devices** (tpmrm0/tpm0 are command-block devices that only accept a sequential read/write stream). So the write failed → the quote could not complete → `GATE FAIL: tpm_quote=FAILED`. **The fix (xdp-7 v2, this session):** in the sentry's `pkg/sentry/fsimpl/gofer/handle.go` + `directfs_inode.go`, detect char devices via `fstat` on the host fd at open time (a new `charDev bool` field on the `handle` struct) and pass `offset = -1` (which `Preadv2`/`Pwritev2` already interpret as a plain `read()`/`write()`, no offset) for them. A belt-and-suspenders fix in the gofer's `openFDLisa.Read/Write` (the RPC fallback path, `h.fd < 0`) does the same.
- **THE FIRST xdp-7 ATTEMPT PATCHED THE WRONG PATH (the key gotcha):** the gofer's `openFDLisa.Read/Write` (in `runsc/fsgofer/lisafs.go`) is the **RPC** path — NOT used when the fd is donated (the `directfs` mount donates the host fd, so the sentry's `handle.go` direct path is the active one). The first xdp-7 (wire pass 4b, `ee61eaeaa8`, AMI `ami-0626b04e08bcdc93c`, `i-0d17c03ef8d5c3d58` @ 77.113.232.245) patched only `lisafs.go` → **identical GATE FAIL** (wrong path).
